## Directory Purposes

**src/**
- Purpose: All source code for the decompiler
- Contains: Rust modules implementing the multi-stage pipeline
- Key files: `main.rs` (entry), `decoder.rs` (parsing), `cfg.rs`, `functions.rs`, `dataflow.rs`, `lifting.rs`, `structuring/*` (analyses)

**src/ir/**
- Purpose: Intermediate representation modules
- Contains: SSA construction for optimization proofs
- Key files: `ssa.rs` (lightweight SSA with value IDs and phi nodes)

**src/structuring/**
- Purpose: Control structure detection and output generation
- Contains: Dominator tree, loop/switch/if-then-else detection, pseudo-code emission
- Key files: `analysis.rs` (dominators + structure detection), `emission.rs` (formatting)

**examples/compiled/**
- Purpose: Test/sample PVM binaries
- Contains: PVM bytecode files (*.pvm) used for integration testing
- Generated by: External PVM compiler (AssemblyScript, WAT)
- Committed: Yes

**examples/output/**
- Purpose: Expected golden output for integration tests
- Contains: Decompiler output files (*.diss) for verification
- Generated by: Running `./run_examples.sh`
- Committed: Yes (to serve as regression baseline)

**examples/sources/**
- Purpose: Original source code for example binaries
- Contains: WebAssembly text format (.wat), AssemblyScript (.ts)
- Committed: Yes (for reference)

**docs/**
- Purpose: Project documentation
- Contains: Output quality metrics, release procedures
- Committed: Yes

**scripts/**
- Purpose: Development and testing utilities
- Contains: Output validation, metrics generation
- Committed: Yes

**.github/**
- Purpose: GitHub CI/CD workflows
- Contains: Test automation, build checks
- Committed: Yes

**.githooks/**
- Purpose: Local git hook scripts
- Contains: Pre-commit (format check), pre-push (lint check)
- Committed: Yes (set via `git config core.hooksPath .githooks`)

**.planning/codebase/**
- Purpose: GSD analysis documents (generated)

## Naming Conventions

**Files:**
- Snake case for Rust modules: `decoder.rs`, `control_flow.rs`, `dataflow.rs`
- Exception: `Cargo.toml`, `README.md`, `.githooks/`, `.github/`
- Output files: `.diss` extension (decompiler disassembly)
- Example source: `.wat` (WebAssembly text), `.ts` (AssemblyScript)

**Directories:**
- Snake case: `src/structuring/`, `src/ir/`
- All lowercase: `examples/`, `docs/`, `scripts/`, `.github/`, `.planning/`

**Rust Items:**
- Modules: Snake case (`dataflow`, `structuring`, `ssa`)
- Types/Structs: PascalCase (`ControlFlowGraph`, `DecodedProgram`, `InstructionShape`)
- Functions: Snake case (`build()`, `detect_functions()`, `analyze()`)
- Enums: PascalCase (`VarType`, `Expression`, `Structure`, `BinOp`)
- Constants: UPPER_SNAKE_CASE (rare in this codebase)

## Where to Add New Code

**New Pipeline Stage (post-lifting):**
- Implementation: Create `src/new_stage.rs`
- Tests: Add tests within `src/new_stage.rs` (inline `#[cfg(test)]` modules)
- Integration: Import in `src/main.rs`, invoke in pipeline
- Call from: `main()` after structuring phase

**New Instruction Classification:**
- Add variant to `BinOp`, `UnaryOp`, or other enums in `src/instruction.rs`
- Update `InstructionShape::classify()` match arms
- Update def-use extraction in same file
- This single change cascades through all consumers (CFG, lifting, etc.)

**New Analysis Module:**
- Create `src/analysis_name.rs` or subdirectory `src/analysis/mod.rs`
- Export from parent module or `src/main.rs`
- Depend on: CFG, instruction classification, potentially dataflow
- Produce: Immutable result structure to pass downstream

**New High-Level Control Structure:**
- Add variant to `Structure` enum in `src/structuring/mod.rs`
- Add detection logic in `src/structuring/analysis.rs`
- Add emission/formatting in `src/structuring/emission.rs`
- Test with example binaries via `./run_examples.sh`

**New Test Binary:**
- Source: Write `.wat` or `.ts` in `examples/sources/`
- Compilation: Use external PVM compiler (outside this repo)
- Binary: Place output in `examples/compiled/my-binary.pvm`
- Golden output: Run `cargo run --release -- examples/compiled/my-binary.pvm > examples/output/my-binary.diss`
- Verify: Check output for correctness, commit `.pvm` and `.diss` files

**Utilities & Helpers:**
- Shared helpers: Add to existing module where they're used (e.g., address formatting helpers in `lifting.rs`)
- Multi-module utilities: Create `src/util.rs` or `src/common/mod.rs`
